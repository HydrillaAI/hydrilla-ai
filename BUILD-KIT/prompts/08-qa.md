# 08 · QA: full pass/fail report

## Goal
Verify the whole `site-rebuild` branch against the kit and produce a pass/fail report. **Fix nothing until you have listed the fixes and Rishi has approved them.** Then apply only approved fixes, re-run the affected checks, and commit.

## Inputs
Kit: `QA-CHECKLIST.md` (run every item), `VERIFY-LIST.md`, `routing.md`, `nav-footer.md`, `pages/*.md`, `seo-geo/*`, `reports/01-audit.md` if present, earlier phase reports.
Runtime: `next build && next start` on `http://localhost:3000`. Scripts go in `<kit>/scripts/` (Node built-ins only; run tools like Lighthouse with `npx` without adding them to `package.json`).

## Checks (each: PASS / FAIL / N/A, with evidence)
1. **QA-CHECKLIST.md:** every item, in order.
2. **VERIFY-LIST.md:** for each item, where it appears in code (file:line) and its status. Any unresolved item = launch-blocking (not a code failure).
3. **Build health:** build, lint, typecheck pass; no new console errors on page load for any kit route.
4. **Routes:** every indexable route in `routing.md` returns 200; noindex routes carry `noindex`; signed-in routes are unchanged.
5. **Redirects:** re-run `check-redirects.mjs`: every source (no-slash, slash, `.md`, query variants) → 301 → final target in one hop → 200. `/bluefox` is 200, `/bluefox3d` → `/bluefox`, no rule has `/bluefox` as a source. Zero chains, zero loops.
6. **Links:** crawl all kit routes from `/`'s nav/footer plus each page's links: no 4xx/5xx, no internal link that hits a 3xx, every `#anchor` target exists. External links: report status, don't fail on rate limits.
7. **Copy exactness:** for each kit page, extract visible `<main>` text from the rendered HTML, normalise whitespace, and diff against the kit copy block minus non-rendered parts (section labels, headline notes, `Visual:` lines, `[VERIFY]` tags, footer notes). Report per page: identical / N differences (show them). Also titles, meta descriptions, OG titles, H1s, button labels, alt text.
8. **Banned terms** (rendered HTML, `.md` mirrors, llms files, metadata, JSON-LD and source outside the kit folder; **exclude the homepage** `/`, its page files and `/index.md`):
   `rg -n "BlueFox 3D|BlueFox3D|Pixal3d|AI for 3D|Blue Fox|Bluefox"` (case-sensitive, so `/bluefox` hrefs don't match; add `rg -n -i "ai for 3d"` for case variants) → 0, except `BlueFox3D` in redirect sources and the Hugging Face href. Also any extra terms in `QA-CHECKLIST.md`. Report homepage hits separately as "homepage, left as is (allowed)".
9. **Homepage diff:** `git diff <default-branch>...site-rebuild` on the homepage page file, its sections, metadata, and `/index.md`, plus a rendered-text diff of `/` (main build vs branch build). **Expected: zero visible changes to homepage body text, sections and components.** Allowed: the new shared header/footer (approved site-wide, must match other pages), and the JSON-LD lab relationship only if Rishi's yes from phase 07 is on record. Any shared-logo change needs Rishi's quoted yes; otherwise FAIL.
10. **Nav/footer:** rendered items match `nav-footer.md` exactly; no duplicates; no noindex/signed-in/redirected targets.
11. **Metadata and schema:** every page: one title ending `| Hydrilla AI` once, ≤ 60 chars if the kit says so, unique; description unique; self-canonical; JSON-LD parses, types match `schema.md`; no node makes Hawan Research Labs Hydrilla's parent, developer or publisher; FAQ/HowTo text matches visible text.
12. **Index files:** sitemap == `PUBLIC_ROUTES` == `routing.md` indexable list; `robots.txt` matches the kit; llms files byte-identical to the kit; every indexable non-home route has a 200 `.md` mirror with the canonical `Link` header; `/md/*` not served as 200.
13. **Accessibility / performance basics (if tooling available):** Lighthouse (mobile) on `/features`, `/bluefox`, `/water`, `/pricing`, `/compare/meshy`: record Performance, Accessibility, SEO, Best Practices; flag a11y issues introduced by this branch (one H1, heading order, alt text, link names, contrast, focus on menus). Compare with the main branch where possible.
14. **Placeholders:** list every `TODO(kit)` and `VERIFY:` comment in code with file:line. Visible `[VERIFY`, `TODO` or `<placeholder>` text on any rendered page = FAIL.
15. **Scope:** no new dependencies without justification; no env/hosting/deploy config changes; no deleted pages outside the kit; branch not pushed or deployed.
